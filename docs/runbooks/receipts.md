# Snap & Split operations

Scanning is off by default. Manual receipt attachment and the existing expense flow work without Google credentials. Development uses a one-second local worker and AES-GCM files below `.local/receipts`; the generated local encryption key must persist with those files. Hosted environments require the private S3 bucket and dedicated receipt worker. No provider, AWS resource or store configuration was created by this implementation.

## Provider enablement

1. Obtain an approved Google project, regional processing/data-use terms and a permissioned evaluation corpus. The adapter is pinned to `asia-south1` and defaults to the evaluation candidate `gemini-3.5-flash`; it cannot fall back to a global endpoint. Verify the exact model's current regional availability, data processing/retention terms, quota and maximum cost before enabling. A regional hostname alone does not establish contractual residency or zero retention.
2. Configure Google Workload Identity Federation for the exact AWS account and the synthesized **ReceiptWorkerRoleArn**. Restrict the AWS provider attribute condition to that account and assumed-role name. Bind that principal to the dedicated service account's workload-identity-user permission; grant that service account only the project's required Vertex prediction access. Review the actual provider IAM mapping before rollout. Do not trust all roles in an AWS account or use downloaded service-account keys.
3. Set `WorkloadIdentityAudience`, `ServiceAccountEmail`, `VertexProject`, `VertexRegion`, `VertexModel` in the existing Secrets Manager configuration. The .NET Google Auth adapter exchanges Lambda's short-lived AWS environment credentials through fixed Google STS/impersonation URLs. It does not accept arbitrary token URLs or fetch EC2 metadata. Test cold start, warm token refresh, expired credentials and denied-role behavior on the actual ARM64 Lambda.
4. Set positive `MonthlyBudgetUsd` and `MaxAttemptCostUsd`. The latter must conservatively bound one maximum three-image, 32,768-output-token request including thinking and applicable regional pricing. Liability is charged for every provider attempt, even timeout/failure; this conservative counter is not a provider invoice. Retries consume another attempt liability. Reconcile aggregate token counts and provider billing separately.
5. Run the protected corpus harness and signed-device journeys. Then set `ProviderValidated=true` and `Enabled=true`. Never set validation true merely because unit tests pass. Configuration secrets load at process startup; use the audited runtime controls for immediate pause/resume.

References: [Google AWS federation](https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-other-clouds), [model candidate](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-5-flash), [locations](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/locations), [retention](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/zero-data-retention).

## Limits and rollback

- Successful readings consume 5 free or 100 verified-subscriber scans per IST calendar month. Failed/not-bill/unreadable results release the reservation. Server billing proof is required; support ad grants and provisional mobile state do not grant paid scans. Three attempts maximum: initial, one automatic retry, one explicit retry. Fenced leases prevent late results from consuming quota twice.
- Each account can admit 10 scans/hour; upload admission separately bounds 10 new sessions/hour, 100 pending drafts and 300 MiB pending upload reservations by default. Each session has ≤3 images, ≤10 MiB each; decoded accepted images have ≤2048 px per side. Review payloads allow 150 items, 20 charges, 50 members and 1.5 MiB canonical JSON over at most 24 pages. No accepted content is silently truncated.
- At 80% of conservative monthly liability, `Budget80` alarms. Free scans pause before exceeding 100%; paid scans may continue. Five consecutive provider failures open a five-minute circuit. `receipt-control stop` stops new scan admission; `pause-free` affects free scans; `resume` clears runtime flags but cannot override disabled configuration. Already admitted work may finish. See [support commands](../../tools/Hisaab.Support/README.md).
- Receipt worker reserved concurrency is four; SQS consumes at most two concurrent batches of one. Stream dispatch reads the durable due time and delays automatic retry wakeups. A one-minute schedule repairs missed wakeups and pages cleanup. Alarms cover worker errors, queue age, DLQ, budget and circuit; connect an operations destination before enabling.

## Access and deletion

Uploads are five-minute signed PUT grants binding content type, length and SHA-256. Untrusted originals land in quarantine. The worker decodes and re-encodes JPEGs, strips metadata and produces thumbnails before exposure or inference. Quarantine has a one-day lifecycle backstop. No signed S3 GET URL is returned. Per-account downloads reserve at most 300 MiB per conservative rolling hour and 60 chunks per UTC minute, including failed reads. Ten-minute image tickets remain bound to account and session; every ≤1 MiB media request rechecks active membership and attachment state. A copied ticket alone does not grant access.

Receipt removal immediately hides media and retains a purge tombstone. Physical deletion runs after ten minutes to cover still-valid PUT grants and in-flight validators. Initial orphan uploads expire after 24 hours; validated private drafts expire after seven days. Non-bill images are queued for one-hour purge; unreadable private drafts retain the seven-day draft deadline so manual attachment remains possible. Expense deletion hides media immediately and retains it through the 30-day restore window. Account deletion anonymizes shared uploaders, cancels private jobs and purges private parsed pages/media. Purge enumerates object versions, including delete markers. These are scheduled targets; operational outages can delay physical deletion, so monitor queues and run deletion/restore drills.

S3 is private, TLS-only, encrypted and retained on stack deletion; deleting the stack does not fulfill retention obligations. No media replication or backups are configured. If restoring database backups, apply deletion tombstones before opening receipt access. Do not remove the retained bucket until an authorized retention/migration procedure has completed.

## Diagnostics and acceptance

Support lookup is ticket/operator audited and returns bounded state, attempts and error metadata only. Raw model text is **not retained**: the plan requires a separate privacy decision before seven-day raw diagnostics can exist. Do not enable verbose provider HTTP tracing. Logs contain aggregate duration, token counts and completion state, never bill text, image bytes, upload URLs or stable account/receipt identifiers.

The evaluation harness reports extraction, exact total/tax and full-item matching by script/category, false positives, latency and token counts without field values. It does not source real receipts or certify production accuracy. A 200+ permissioned real-bill corpus, no-regression candidate comparison, actual billing reconciliation, upload-complete→ready latency, production IAM/load/deletion drills and physical-device acceptance remain release gates. Production correction/conversion analytics are not implemented; no claim of measured edit rate is made.
