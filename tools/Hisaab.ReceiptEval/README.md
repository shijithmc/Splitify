# Protected receipt evaluation

This tool calls the same normalization, Mumbai Vertex adapter and strict parser as the receipt worker. No real corpus ships in Git. No evaluation result or accuracy claim exists until an authorized operator supplies the protected corpus and runs it.

Keep images, labels, credentials and reports outside the checkout. Manifest: JSON array of `EvaluationCase` objects with `id`, `category`, `script`, `images` (1–3 normalized JPEG/PNG paths relative to the manifest), `contributorPermission: true`, `classification` (`bill` or `not_bill`), and `expected` (the complete `ReceiptReview` JSON for bills, null for negative examples). Expected values come from independent human labels, not a previous model output. Use INR bills with exact integer-paise expected totals, items and all tax lines. Include at least 200 bills, all five categories (`restaurant`, `grocery`, `fuel`, `pharmacy`, `handwritten`), at least five script labels and negative examples. Review label consistency separately; a permission boolean is an operator attestation, not proof of consent.

```sh
dotnet run --project tools/Hisaab.ReceiptEval -- validate /secure/corpus/manifest.json /secure/reports/validation.json
```

Validation performs no provider calls. It checks every image with the production decoder before a run can send its first case. For a paid run, configure the same keyless Vertex environment settings listed in `.env.example`, including `ProviderValidated=true`. Set `HISAAB_EVAL_SEND_TO_PROVIDER=yes` only after authorization to send this specific corpus. Then replace `validate` with `run`. The tool sends each case once, sequentially; it does not silently retry or collect a corpus from user receipts. Local working images are AES-GCM encrypted using an ephemeral in-memory key and removed after each case and on exit. A killed process may leave ciphertext in the OS temporary directory; no key is persisted.

Reports contain aggregate counts by category/script, provider token counts and nearest-rank p50/p90/p95. Bill accuracy denominators include failed/unreadable/provider-error cases. Total/tax exact requires grand total and every tax name, amount and inclusive flag to match. Item exact requires the complete normalized name/quantity/unit/line-total multiset to match. Non-bill false positives have a separate denominator. Provider errors and missing usage remain visible. Reports omit case IDs, names, field values and images; suppress small-category reports before external sharing if necessary.

Exit 0 requires ≥92% valid readings and ≥85% total/tax exact; otherwise exit 1. This is an accuracy gate, not blanket release approval. Compare candidate and baseline on the identical frozen corpus and inspect every script/category for regressions. Review statistical uncertainty when a category is small. Reconcile input/output/thinking tokens and failed attempts with current regional pricing and the provider billing export before asserting cost per successful scan. Timing includes local normalized-image reads, federation, inference and parsing; it excludes upload/queue/mobile time and cannot prove the product's end-to-end latency target. Native camera, handwriting, provider residency and production IAM still require their own acceptance evidence.
